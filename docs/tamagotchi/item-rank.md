## เป้าหมาย

1. **เกรด** เป็นตัวกำหนดความแรงของอุปกรณ์ชัดเจนขึ้น: ตัวคูณค่าหลัก, จำนวนค่ารอง, โอกาสได้ Special Option
2. **ค่าสุ่ม (ค่ารอง)** สุ่มจากพูลเดียวกัน ไม่ซ้ำ ไม่ซ้ำกับค่าหลัก ช่วงค่าขึ้นกับเกรด
3. **Special Option** สำหรับมอนเลี้ยงโดยเฉพาะ (ลดความหิว, เร่งโต, โอกาสวิวัฒนาการ ฯลฯ) ไม่ใช่ค่าต่อสู้

ไม่แตะ: กติกาตีบวก, ราคาและอัตราสุ่มของกล่อง (ยกเว้นข้อที่ระบุ)

## กติกา (backend `src/modules/monster/`)

ค่าทั้งหมดอยู่ใน `equipment-data.ts` / `monster-rules.ts` เผยแพร่ผ่าน `GET /monster/wiki` ตามเดิม

### เกรด

| เกรด | ตัวคูณค่าหลัก (เดิม) | ค่ารอง (จำนวน) | โอกาสมี Special | ค่า Special |
|---|---|---|---|---|
| ธรรมดา | ×1 | 0–1 | 0% | – |
| หายาก | ×1.5 | 1–2 | 15% | 50–70% ของช่วง |
| มหากาพย์ | ×2.2 | 2–3 | 50% | 70–90% ของช่วง |
| ตำนาน | ×3 | 3–4 | 100% (+25% ได้ตัวที่ 2) | 90–100% ของช่วง |

- ตัวคูณค่าหลัก **คงตามเดิม** ของเฟส 3 (1 / 1.5 / 2.2 / 3) ไม่เปลี่ยน
- จำนวนค่ารองเปลี่ยนจากเดิม "1–3 ทุกเกรด" เป็นตามเกรดในตาราง
- **ชิ้นเซ็ตสุ่มค่ารองและมี Special เหมือนชิ้นธรรมดา** ตามเกรด (ใช้ฟังก์ชัน `rollRandomStats` ตัวเดียวกัน) ค่าหลักยังสูงกว่าชิ้นธรรมดา (`SET_PIECE_MAIN_MULTIPLIER`) · ชิ้นเซ็ตที่ได้ก่อนการเปลี่ยนนี้คงค่าตายตัวเดิม ไม่ backfill · รางวัล World Boss สุ่มด้วย seed จาก `claimRolls` ต่อ จึงได้ค่าเดิมเมื่อรับซ้ำ

### ค่ารอง (random status)

- พูล: `hp, atk, def, spd` (มีอยู่แล้ว) · พูลขยาย `critRate, critDamage, evasion` เปิดใช้เมื่อ battle engine รองรับ (ดู "ที่ต้องยืนยัน" ข้อ 2)
- สุ่มจำนวนตามเกรด → สุ่มค่าจากพูลโดยตัด **ค่าหลักของช่อง** และตัวที่ซ้ำออก → ค่า = สุ่มใน [min, max] ของค่านั้น × ตัวคูณเกรด ปัดเป็นจำนวนเต็ม อย่างน้อย 1
- เก็บเป็นตัวเลขตายตัวในแถวของชิ้น (flat) เหมือนเดิม

### Special option

| Option | ผล | ช่วงค่าพื้นฐาน |
|---|---|---|
| Slow Hunger | ลดอัตราความอิ่มลด | 5–15% |
| Quick Growth | เพิ่มความเร็ววิวัฒนาการ | 5–20% |
| Lucky Evolve | เพิ่มโอกาสร่างหายาก/ร่างลับ | 3–10% |
| Stamina Saver | ลด stamina ที่ใช้ผจญภัย | 5–15% |
| Hardy Care | ลดโอกาสป่วย | 10–30% |
| Treasure Nose | เพิ่มโอกาสดรอป | 5–15% |
| Tidy Pet | ลดอัตราอึ | 10–25% |

- มีได้สูงสุด 2 ต่อชิ้น (เฉพาะตำนาน), ไม่ซ้ำกันในชิ้นเดียว
- ค่า = `min + (max − min) × t` โดย `t` สุ่มในช่วงของเกรด (ตาราง)
- **รวมค่าแบบบวกกัน** ข้ามชิ้นที่สวมอยู่ และมีเพดานรวมต่อ option (เสนอ: ไม่เกิน 2× ค่า max ของ option) กัน stack เกินคุม
- **คำนวณใหม่ทุกครั้ง** จากชิ้นที่สวมอยู่ ไม่เก็บค่าที่คำนวณแล้ว (แบบเดียวกับโบนัสเซ็ต) มอนที่ไม่สวมของไม่ได้ผล
- ใช้ใน `tick()` (ความหิว/อึ/ป่วย/วิวัฒนาการ) และ service ผจญภัย/ดรอป → pure function `calcSpecialBonuses(equippedItems)` ตัวเดียว ให้ทุกที่เรียก ห้ามกระจายสูตร
- ผลของ option ต้องไม่ทำให้ `tick()` ย้อนหลังผิด: ใช้ชุดอุปกรณ์ ณ ตอนคำนวณ (ยอมรับความคลาดเคลื่อนตอนปิดแอป ตามที่ระบุใน wiki)

### การสุ่ม

- สุ่มบนเซิร์ฟเวอร์เสมอ ผ่าน RNG ตัวเดิมของ equipment (รับ seed ได้เพื่อทดสอบ) บันทึกใน `equipment_logs` ทุกครั้งที่ได้ชิ้น (รวมค่ารองและ Special ที่ออก)
- ฟังก์ชันสุ่มเป็น pure: `rollEquipment(template, grade, rng)` → `{ mainValue, subStats, specialOptions }`

## เกรดขั้นต่ำของร่างที่สวมได้

ต้องวิวัฒนาการถึงร่างขั้นต่ำก่อนจึงสวมชิ้นเกรดนั้นได้ (`MIN_STAGE_BY_GRADE`, ตรวจด้วย `canEquip` ใน `EquipmentService.equip` เมื่อสวม ส่ง 400 ถ้าร่างอ่อนเกินไป)

| เกรด | ร่างขั้นต่ำ |
|---|---|
| ธรรมดา | ไม่มี |
| หายาก | ร่างโต (adult) |
| มหากาพย์ | ร่างสมบูรณ์ (perfect) |
| ตำนาน | ร่างสมบูรณ์ (perfect) |

- ร่างรวม (fused) นับว่าสูงกว่าร่างสูงสุด · ใช้กับชิ้นเซ็ตเหมือนกัน
- ชิ้นที่สวมอยู่แล้วไม่ถูกตรวจซ้ำ (grandfather) ไม่มี migration
- `GET /monster/wiki` ส่ง `equipment.minStageByGrade` และแต่ละชิ้นส่ง `minStage` · หน้าจอล็อกปุ่มสวมพร้อมเหตุผล
- ไม่เปลี่ยนอัตราดรอป ราคา การตีบวก และการแยกชิ้น

## ข้อมูล

- migration ใหม่: เพิ่มคอลัมน์ `special_options jsonb NOT NULL DEFAULT '[]'` ในตารางอุปกรณ์ (`[{ key, value }]`)
- ชิ้นเดิมไม่แก้ (ดู "ที่ต้องยืนยัน" ข้อ 4)
- ไม่มีข้อมูลส่วนบุคคลเพิ่ม (PDPA: ผูกกับ `user_id` ที่มีอยู่เท่านั้น, ไม่เพิ่มข้อมูลระบุตัวตนใน log)

## API

- `GET /monster/equipment` ส่ง `specialOptions` เพิ่มในแต่ละชิ้น และ `specialTotals` (ผลรวมที่สวมอยู่ หลังเพดาน)
- `GET /monster/wiki` ส่งตารางเกรด, พูลค่ารอง, รายการ Special พร้อมช่วงค่า (frontend ไม่ hardcode)
- action เดิม (สวม/ถอด/ตีบวก/แยกชิ้น) ไม่เปลี่ยน signature

## Frontend (`src/pages/project/tamagotchi/`)

- `EquipmentPanel.tsx`: การ์ดชิ้นแสดงสีตามเกรด, ค่ารอง, บล็อก ✨ Special; การเทียบกับชิ้นที่สวมอยู่รวม Special
- สรุป Special ที่ได้รับรวมแสดงที่ `StatusPanel.tsx` (เช่น "ลดความหิว 12%")
- เปิดกล่องสุ่มแสดงชิ้นที่ได้พร้อม Special
- Wiki: ส่วนเกรด/ค่ารอง/Special ดึงจากเซิร์ฟเวอร์

## ทดสอบ

- unit (pure, seeded): `rollEquipment` จำนวนค่ารองต่อเกรด, ไม่ซ้ำ/ไม่ชนค่าหลัก, ช่วงค่า, โอกาส Special (จำลอง 10,000 รอบ ตรงโอกาสในตารางในกรอบที่ยอมรับ), ตำนานได้ตัวที่ 2 ~25%
- unit: `calcSpecialBonuses` รวมแบบบวก + เพดาน, ไม่สวมของ = 0
- integration (Postgres จริง): ได้ชิ้นแล้วเก็บ `special_options`, สวม/ถอดแล้ว `specialTotals` ถูก, `tick()` ใช้ Slow Hunger/Tidy Pet ถูก
- frontend: การ์ดชิ้นแสดง Special, ไม่มี Special แสดงว่าไม่มี

## ลำดับทำงาน

## ที่ต้องยืนยันก่อนเริ่ม

1. ตัวเลขในตารางเกรด / ช่วงค่ารอง / รายการและช่วงค่า Special ใช้ได้ไหม มีอยากเพิ่ม/ตัดตัวไหน
2. พูลขยาย (`critRate, critDamage, evasion`): battle engine ต้องรองรับก่อน ทำพร้อมกันหรือแยก PR (แนะนำแยก เริ่มด้วย 4 ค่าเดิม)
3. Reroll (ใช้หิน/วัตถุดิบสุ่มค่ารองหรือ Special ใหม่): ยังไม่ออกแบบ ต้องการไหม
4. ชิ้นเดิมในกระเป๋า: คงเดิม (แนะนำ) หรือสุ่มค่าใหม่ให้ (backfill)
5. เพดานรวมของ Special (เสนอ 2× ค่า max) และ option ที่กระทบเศรษฐกิจ (Treasure Nose) ต้องจำกัดเพิ่มไหม
