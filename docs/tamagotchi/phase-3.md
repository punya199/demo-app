## ขอบเขต

**ทำในเฟสนี้**
- อุปกรณ์ 4 ช่อง: อาวุธ · เกราะ · หมวก · เครื่องประดับ เกรด ธรรมดา → หายาก → มหากาพย์ → ตำนาน
- อุปกรณ์ผูกกับ **ผู้ใช้** ไม่ใช่ตัวมอน (เหมือนคลังไอเทมและความคืบหน้าผจญภัย) สวมใส่กับมอนที่มีชีวิตตัวปัจจุบัน ตัวเก่าตายแล้วอุปกรณ์ยังอยู่ ส่งต่อให้ตัวใหม่ได้ตามหลักการใน roadmap โดยไม่ต้องมีขั้นตอนพิเศษ
- ตีบวกที่อุปกรณ์ ตามตารางอัตราใน roadmap
- โครงโบนัสเซ็ต 2/4 ชิ้น (`setId` ตั้งแต่เฟสนี้ ผสม 2+2 ได้) แต่ **ยังไม่มีชิ้นเซ็ตดรอป** เพราะบอสประจำเซ็ตอยู่เฟส 5 ทดสอบตัวคำนวณด้วยเซ็ตตัวอย่างใน spec

**ยังไม่ทำ**
- ชุดเซ็ตจากบอส, Boss Token, Raid Token (เฟส 5)
- EXP ยังไม่มี (ไม่จำเป็นต่อเฟสนี้)
- ค่ารองสุ่มของชิ้นเซ็ต (เซ็ตเป็นค่าตายตัว ไว้เฟส 5)

## กติกา (backend `src/modules/monster/`)

ค่าทั้งหมดอยู่ใน `monster-rules.ts` และ `equipment-data.ts` เผยแพร่ผ่าน `GET /monster/wiki` ตามเดิม

### ชนิดอุปกรณ์ (`equipment-data.ts`)

| ช่อง | ค่าหลัก |
|---|---|
| ⚔️ อาวุธ | ATK |
| 🛡️ เกราะ | DEF |
| ⛑️ หมวก | HP |
| 💍 เครื่องประดับ | SPD |

- แม่แบบอุปกรณ์เป็นข้อมูล (`id`, ชื่อ, emoji, ช่อง, `setId | null`) เพิ่มของได้โดยไม่แก้โค้ด
- **ค่าหลัก** = ค่าฐานของช่อง × ตัวคูณเกรด (ธรรมดา 1 · หายาก 1.5 · มหากาพย์ 2.2 · ตำนาน 3)
- **ค่ารอง** (ไอเทมธรรมดา): สุ่ม 1–3 ค่าตอนได้ชิ้น เก็บเป็นตัวเลขตายตัวในแถวของชิ้น เกรดสูงได้ช่วงค่าสูงกว่า
- ค่าเป็นแบบ **บวกตัวเลขตรง ๆ** (flat) เข้ากับค่าพลังของมอน ไม่ใช่เปอร์เซ็นต์ จึงไม่พังเมื่อมอนวิวัฒนาการ (ร่างสูงกว่า ค่าฐานสูงกว่า อุปกรณ์เดิมยังช่วยเท่าเดิม)

### เข้าสู่การต่อสู้

- `toFighter(state)` ใน `battle-stats.ts` รับโบนัสอุปกรณ์เพิ่มอีกหนึ่งพารามิเตอร์ (`IBattleStats`) บวกหลังคำนวณค่าพื้นฐานและก่อนตัวคูณ stamina หมด (ครึ่งหนึ่ง) `IMonsterState` ไม่เปลี่ยน
- `AdventureService` และ `ExpeditionService` โหลดอุปกรณ์ที่สวมอยู่ภายใน transaction เดียวกับที่ล็อกมอน คำนวณโบนัสใหม่ **ทุกครั้ง** (ไม่เก็บค่าที่คำนวณแล้ว) อัตราสำรวจที่ล็อกตอนออกเดินทางจึงรวมอุปกรณ์ ณ ตอนนั้น
- สวมได้ช่องละ 1 ชิ้น ใช้ partial unique index `(user_id, slot) WHERE equipped` กันสวมซ้ำช่อง
- สวม/ถอดทำได้ตลอด ยกเว้นระหว่างสำรวจ (กันสลับของก่อนเก็บรางวัลเพื่อเพิ่มอัตรา)

### โบนัสเซ็ต

- `calcSetBonuses(equippedItems)` เป็น pure function นับชิ้นต่อ `setId` ที่สวมอยู่: 2 ชิ้นได้โบนัส 2 ชิ้น, 4 ชิ้นได้ทั้งสองระดับ ผสม 2+2 ข้ามเซ็ตได้
- เฟส 3 รองรับโบนัสแบบ **ค่าพลัง** (ATK/DEF/HP/SPD เป็นเปอร์เซ็นต์) ส่วนโบนัสพิเศษใน battle engine (เผาไหม้, โล่, ฟื้น HP, โจมตีซ้ำ, ชุบชีวิต) ทำพร้อมชิ้นเซ็ตในเฟส 5

### ที่มาของอุปกรณ์

| ที่มา | รายละเอียด |
|---|---|
| 🎁 กล่องสุ่มอุปกรณ์ (ร้านค้า) | ราคา 🪙 และ **แสดงอัตราเกรดในหน้าร้าน** สุ่มบนเซิร์ฟเวอร์ ได้เกรดธรรมดา/หายากเป็นหลัก มหากาพย์น้อย ไม่มีตำนาน |
| ⚔️ ดรอปจากชนะด่านผจญภัย (สู้เอง) | โอกาสต่ำต่อครั้ง เกรดตามพื้นที่ (ทุ่งหญ้า ธรรมดา · ชายฝั่ง ธรรมดา/หายาก · ภูเขาไฟ หายาก/มหากาพย์) ต่อสู้อัตโนมัติและสำรวจไม่ดรอป กันปั๊มของ |
| 🧭 สำรวจ | หินตีบวก 1 ก้อนต่อชั่วโมงที่สำรวจ (นอกเหนือจากไอเทมสะสมเดิม) ไม่ดรอปอุปกรณ์ |

- สุ่มทุกครั้งทำบนเซิร์ฟเวอร์ บันทึก log (`monster_logs` / `equipment_logs`)
- กระเป๋าอุปกรณ์มีเพดานจำนวนชิ้น (เริ่มต้น 50) เต็มแล้วดรอปไม่เข้า แจ้งผู้เล่น ไม่ทิ้งเงียบ ๆ

### วัตถุดิบ

- ใช้ตาราง `inventory_items` เดิม (ไอเทมเป็น `item_id` เพิ่มประเภทใหม่ ไม่ต้องมีตารางใหม่) แต่ไม่ใช่ไอเทมที่ใช้กับมอน ไม่เข้า `applyShopItem`
- `enhance_stone` หินตีบวก: ได้จากสำรวจ (1 ก้อน/ชม.), แยกชิ้นส่วน, หรือซื้อในร้าน 🪙 40
- `protect_scroll` ใบกันแตก: ขายในร้านด้วย 💎 5 (เพชรยังมีที่ใช้น้อย) จนกว่า Raid Token จะมาในเฟส 5 **(เฟส 5a ย้ายไปขายด้วย 🎖️ 6 แล้ว)**

## ตีบวก (3b)

อุปกรณ์แต่ละชิ้นมี `enhance_level` 0–15 บวกเพิ่มค่าหลัก (+8% ของค่าหลักฐานต่อระดับ) และโบนัสพิเศษทุก 5 ระดับ (+5, +10, +15)

| ระดับ | อัตราสำเร็จ | ถ้าล้มเหลว |
|---|---|---|
| +1 ถึง +5 | 100% | – |
| +6 ถึง +9 | 80% → 50% | เสียวัตถุดิบ |
| +10 ถึง +12 | 40% → 20% | ระดับลด 1 |
| +13 ถึง +15 | 15% → 5% | ระดับลด 1 หรือแตก (50/50) |

- **ค่าใช้จ่ายต่อครั้ง:** 🪙 `10 × ระดับเป้าหมาย²` + หิน `1 + ⌊(ระดับเป้าหมาย−1)/3⌋` ก้อน (เหรียญเป็น sink หลักของเกม) **ใช้ทุกครั้งที่ลอง** ไม่ว่าสำเร็จหรือไม่ ล้มเหลวที่ +6 ขึ้นไปเสียทรัพยากรแต่ชิ้นยังอยู่ ยกเว้นช่วง +10 ขึ้นไปที่อาจลดระดับ/แตก
- **Pity:** นับล้มเหลวติดกันต่อชิ้น (`pity`) เพิ่มอัตราสำเร็จครั้งละ +2% สูงสุด +20% รีเซ็ตเมื่อสำเร็จ
- **แสดงอัตราจริง:** `GET /equipment/:id/enhance-preview` คืนอัตรารวม pity, ค่าใช้จ่าย และผลถ้าล้มเหลว หน้าจอแสดงตัวเลขเหล่านี้ก่อนกดเสมอ
- **ใบกันแตก:** ใช้ได้เมื่อระดับที่กำลังตีมีโทษล้มเหลวแบบลดระดับ/แตก (+10 ขึ้นไป) ล้มเหลวแล้วไม่ลดระดับและไม่แตก **ตัดใบก่อนสุ่มแล้วคืนให้ถ้าไม่ได้ใช้จริง** (ถ้าเช็คหลังสุ่ม ผู้เล่นที่ไม่มีใบจะสุ่มซ้ำฟรีได้ เพราะ transaction ที่ล้มเหลว rollback ทั้งผลสุ่ม)
- **แยกชิ้นส่วน** (`dismantle`): ทำลายชิ้นที่ไม่สวมอยู่ ได้หินตามเกรดและระดับบวก ไม่สวมอยู่เท่านั้นกันเผลอ
- **บันทึกทุกครั้ง:** `enhance_log` เก็บ ก่อน/หลังระดับ, อัตราที่ใช้, ผล, ค่าใช้จ่าย, pity

### ความปลอดภัยของการสุ่มและเงิน

- ทั้งหมดใน DB transaction เดียว ล็อกแถวอุปกรณ์ (`pessimistic_write`) → ตรวจกติกา → ตัดเหรียญ/หิน/ใบกันแตก (`WalletService.change` และ `UPDATE ... WHERE quantity >= n`) → สุ่มด้วย `crypto.randomInt` → บันทึกผล ตามหลัก "ตรวจก่อน ตัดเงินทีหลัง" ของโมดูล
- client ส่งแค่ `equipmentId` และว่าจะใช้ใบกันแตกไหม ไม่ส่งอัตราหรือผล

## API (ทุก route ใช้ `@AuthUser()`)

| Method | Path | Body | ผล |
|---|---|---|---|
| GET | `/equipment` | – | `{ capacity, items, setBonuses, bonus, stats }` (`stats` = ค่าพลังมอนที่มีชีวิตรวมอุปกรณ์ที่สวม) |
| POST | `/equipment/equip` | `{ equipmentId }` | ข้อมูลเดียวกับ `GET /equipment` |
| POST | `/equipment/unequip` | `{ slot }` | ข้อมูลเดียวกับ `GET /equipment` |
| POST | `/shop/buy-box` | – | `{ wallet, item }` (กระเป๋าเต็ม = 400 และไม่ตัดเงิน) |
| POST | `/shop/buy-material` | `{ itemId: 'enhance_stone' \| 'protect_scroll' }` | `{ wallet, items }` |
| GET | `/equipment/:id/enhance-preview` | – | อัตรา, ค่าใช้จ่าย, ผลถ้าล้มเหลว |
| POST | `/equipment/enhance` | `{ equipmentId, useProtect }` | `{ result, wallet, equipment, inventory }` |
| POST | `/equipment/dismantle` | `{ equipmentId }` | `{ gained, ...GET /equipment }` |

- `POST /adventure/battle` ผลการต่อสู้เพิ่ม `drop` (ชิ้นที่ดรอป หรือ null)
- `IMonsterView` ไม่เปลี่ยน ค่าพลังที่รวมอุปกรณ์อยู่ใน `GET /equipment` (`stats`) เพื่อให้ frontend แสดงโดยไม่คำนวณเอง

## ข้อมูล (migration `1790500000000-add-equipment`, `1790600000000-add-enhance-log`)

```
equipment_items  { user_id, template_id, slot, set_id, grade, main_value, sub_stats jsonb,
                   enhance_level, pity, equipped, + audit }
                 unique (user_id, slot) WHERE equipped AND deleted_at IS NULL
equipment_logs   { user_id, equipment_id, type, payload jsonb }        -- ได้มา/สวม/ถอด/แยก
enhance_logs     { user_id, equipment_id, from_level, to_level, rate, success, broke,
                   cost jsonb, pity_before }
```

- แตก = soft delete (`deleted_at`) ตามกฎของ repo ไม่ลบจริง

## ทดสอบ

- `equipment-data.spec.ts`: ค่าหลัก/รองตามเกรด, `calcSetBonuses` (2, 4, ผสม 2+2, ชิ้นเดียวไม่ติด)
- `battle-stats.spec.ts`: โบนัสอุปกรณ์เข้า `toFighter` และ stamina หมดยังครึ่งหนึ่งของค่ารวม
- `enhance-engine.spec.ts` (pure, seeded RNG): อัตราต่อระดับ, pity ขึ้นและรีเซ็ต, ผลล้มเหลวแต่ละช่วง, ใบกันแตก, ห้ามเกิน +15
- **สมดุล:** จำลองตีบวกหลายพันครั้ง ต้นทุนเฉลี่ยไป +10 / +15 อยู่ในกรอบที่กำหนด (เหรียญไม่ล้นตลาดเมื่อเทียบรายได้สำรวจ/ผจญภัยต่อวัน) และกล่องสุ่มให้อัตราเกรดตรงตาราง
- ต่อสู้ด้วยอุปกรณ์ +ค่าสูงสุด ต้องไม่ทำให้ด่านบอสสุดท้ายชนะง่ายกว่าร่างสูงสุดเกินกรอบ (รันชุดทดสอบสมดุลเดิม 500 seed ซ้ำพร้อมอุปกรณ์สูงสุด)
- race: ตีบวกพร้อมกัน 6 request ต้องผ่านเท่าที่หิน/เหรียญพอ (ต้องมี DB จริง ทำเป็น integration test เหมือน `yarn test:integration`)

## ผลที่ทำจริง

- **สมดุลตีบวก** (จำลอง 200 ครั้งต่อเป้า, pity เปิด, ใบกันแตกตั้งแต่ +10): +5 ≈ 550 🪙 / 7 หิน · +8 ≈ 2,700 / 18 · +10 ≈ 8,900 / 42 · +12 ≈ 18,000 / 70 / ใบกัน 5 · **+15 ≈ 53,000 🪙 / 156 หิน / ใบกัน 19 ใบ (💎 ~95)** เทียบรายได้ ภูเขาไฟสำรวจ 8 ชม. ≈ 4,400 🪙 และ 8 หิน
- **ทดสอบกับ Postgres 16 จริง** (migration `1790500000000`, `1790600000000` ผ่าน): ตีบวกพร้อมกัน 6 request เมื่อหินพอ 3 ครั้ง ผ่านพอดี 3, สวมชิ้นใหม่แทนชิ้นเดิมในช่องเดียวกัน (partial unique index), แตก = soft delete, แยกชิ้นส่วนได้หิน, กล่องสุ่มตอนกระเป๋าเต็มไม่ตัดเงิน, ขอใบกันแตกที่ไม่มีถูกปฏิเสธก่อนสุ่มโดยไม่เสียเหรียญ/หิน
- **ข้อจำกัดที่ยอมรับ:** สวม/ถอดพร้อมกันของผู้ใช้ที่ยังไม่มีมอน ไม่มีล็อกแถวมอนมาต่อคิวให้ ถ้าชนกันจะโดน unique index ปฏิเสธ (500) ไม่เกิดข้อมูลเสีย
- ค่าอุปกรณ์รวมในการต่อสู้และอัตราสำรวจ (อัตราล็อกตอนออกเดินทางรวมอุปกรณ์ ณ ตอนนั้น) แต่ยังไม่ได้รันชุดทดสอบสมดุลบอสซ้ำพร้อมอุปกรณ์สูงสุด เพราะสูงสุดที่หาได้ในเฟสนี้คือมหากาพย์ (กล่องสุ่มไม่มีตำนาน) ควรทำพร้อมชิ้นเซ็ตเฟส 5
