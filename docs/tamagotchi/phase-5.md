## ขอบเขต

**ทำในเฟสนี้**
- ชุดเซ็ต 4 ชุดจากบอส (เพลิงกัลป์ · วารีพิทักษ์ · รากแก้ว · สายฟ้าเร็ว) ตามตารางใน roadmap รวมโบนัส 4 ชิ้นแบบมีเอฟเฟกต์ในการต่อสู้
- Boss Raid เดี่ยว 3 บอสประจำธาตุ × 3 ระดับ (Normal / Hard / Nightmare)
- World Boss 1 ตัวต่อสัปดาห์ (ตอนนี้มี ⚡ จักรกลพายุ ตัวเดียว หมุนเวียนจากตารางข้อมูล)
- Raid Token (สกุลใหม่ในกระเป๋าเงิน) และ Boss Token (รายบอส)
- เพื่อน, เยี่ยมมอน, ของขวัญ, ตัวซัพพอร์ตสำหรับเช่า (ใช้ได้ใน World Boss เท่านั้น ห้ามใช้ใน PvP)

**ยังไม่ทำ**
- Party Boss Raid และชุดผู้นำทัพ (เฟส 7), Realtime PvP (เฟส 6)
- ตัวเช่าใน Party Raid (เฟส 7) แต่เอนจินทีมที่ทำในเฟสนี้เป็นฐานให้
- Event ตามเทศกาล, push notification

## เอฟเฟกต์ชุดเซ็ตในเอนจินต่อสู้ (5a)

ข้อสำคัญที่สุดของเฟสนี้: **ห้ามทำให้ replay ของการต่อสู้เก่าเปลี่ยนผล** ประวัติ PvP เก็บ seed + ค่าพลังทั้งสองฝั่งแล้วจำลองซ้ำเมื่อกดดู ถ้าเพิ่มเอฟเฟกต์แล้วลำดับการสุ่มเปลี่ยน ประวัติเก่าจะแสดงผลผิดจากที่เกิดจริง

- `IFighter` เพิ่มฟิลด์ **ไม่บังคับ** `effects` (`burnTurns`, `shieldPct`, `regenPct`, `doubleStrikeChance`) fighter ที่ไม่มี `effects` ต้องผ่านเส้นทางโค้ดเดิม **โดยไม่มีการเรียก RNG เพิ่ม** แม้แต่ครั้งเดียว
- เอฟเฟกต์ที่ต้องสุ่ม (โจมตีซ้ำ 20%) เรียก RNG เฉพาะเมื่อ fighter มี `doubleStrikeChance`
- มี golden test: ชุด (fighter, seed) หลายสิบชุดจากเอนจินปัจจุบัน ผลต้องเหมือนเดิมทุกบิต หลังเพิ่มเอฟเฟกต์
- `toFighter` อ่านเอฟเฟกต์จากเซ็ตที่สวมอยู่ (`calcSetBonuses` มีตัวนับชิ้นอยู่แล้ว เพิ่ม `effect` ในนิยามเซ็ต) snapshot ทีมป้องกัน PvP จึงพกเอฟเฟกต์ไปด้วยโดยอัตโนมัติ

| เซ็ต | 2 ชิ้น | 4 ชิ้น | เอฟเฟกต์ในเอนจิน |
|---|---|---|---|
| 🔥 เพลิงกัลป์ | ATK +15% | เผาไหม้ 3 เทิร์น | ท่าสกิลที่โดนติดเผาไหม้ ทุกเทิร์นเสียดาเมจ 25% ของ ATK ผู้ใช้ ไม่ซ้อนทับ (ต่ออายุ) |
| 💧 วารีพิทักษ์ | DEF +20% | โล่เริ่มต้น | เริ่มสู้ด้วยโล่ 15% ของ HP สูงสุด ดูดดาเมจก่อน HP |
| 🌿 รากแก้ว | HP +20% | ฟื้นทุกเทิร์น | ฟื้น 5% ของ HP สูงสุดทุกครั้งที่ถึงเทิร์นตัวเอง |
| ⚡ สายฟ้าเร็ว | SPD +15% | โจมตีซ้ำ | 20% ที่จะโจมตีอีกครั้งทันที (ไม่ซ้อนซ้ำเป็นลูกโซ่) |

- เซ็ตเป็นข้อมูล (`SET_DEFINITIONS` ใน `equipment-data.ts` ที่ตอนนี้ว่างอยู่) เพิ่มเซ็ตใหม่ได้โดยไม่แก้เอนจิน ถ้าใช้เอฟเฟกต์ที่มีอยู่
- ชิ้นเซ็ตมี **ค่ารองตายตัว** (ไม่สุ่ม) ตามแม่แบบ ค่าหลักสูงกว่าชิ้นธรรมดาเกรดเดียวกัน
- **แรงขึ้นที่ +10:** ถ้าทุกชิ้นของเซ็ตที่สวมอยู่ตีบวกถึง +10 ขึ้นไป โบนัสเปอร์เซ็นต์ของเซ็ตนั้นคูณ 1.5 (ไม่รวมเอฟเฟกต์ 4 ชิ้น)

## Boss Raid เดี่ยว (5a)

| บอส | ธาตุ | เซ็ตที่ดรอป |
|---|---|---|
| 🔥 ราชันย์ลาวา | เพลิง | เพลิงกัลป์ |
| 💧 อสูรห้วงลึก | วารี | วารีพิทักษ์ |
| 🌿 พฤกษาโบราณ | พฤกษ์ | รากแก้ว |

- สู้ด้วยเอนจิน 1 ต่อ 1 เดิม (`simulateBattle` ต้องชนะภายใน 20 รอบ) บอสเป็น `IFighter` ที่ปรับสเกลตามระดับ **แต่ปิดตารางธาตุ** (`ignoreElements`) ดู "ผลที่ทำจริง (5a)" ว่าทำไม
- **เงื่อนไขเข้า:** Normal ต้องร่างโตขึ้นไป · Hard ต้องร่างสมบูรณ์ขึ้นไป · Nightmare ต้องร่างสูงสุด (ตรวจที่เซิร์ฟเวอร์ ระดับถัดไปปลดล็อกเมื่อชนะระดับก่อนหน้าของบอสนั้น)
- สู้ได้วันละ 3 ครั้ง (รวมทุกบอส ตามวันเวลาไทย) ใช้ stamina 10 เหมือนผจญภัย ไม่ใช้ได้ตอนป่วย/ออกสำรวจ/ตัวเช่าไม่เกี่ยว (เดี่ยว)
- ชนะ: ได้ **1 ชิ้นเซ็ตของบอส** (สุ่มช่อง ช่องละ 25%) เกรดตามระดับ (Normal หายาก · Hard มหากาพย์ · Nightmare ตำนาน) + 🎫 Boss Token ของบอสนั้น + 🎖️ Raid Token ชนะครั้งแรกของแต่ละระดับให้ x2
- **แพ้:** ไม่ได้อะไร ยังเสียโควตาและ stamina
- สุ่มบนเซิร์ฟเวอร์ บันทึก log (`equipment_logs` มี source `raid:<boss>:<difficulty>`) กระเป๋าเต็มแล้วดรอปไม่เข้า แจ้งผู้เล่นเหมือนดรอปผจญภัย **และไม่ตัดโควตาของวัน** เมื่อกระเป๋าเต็ม (ปฏิเสธก่อนสู้ ไม่ปล่อยให้ชนะแล้วของหาย)

### สกุลใหม่: Raid Token และ Boss Token

| | ได้จาก | ใช้ทำอะไร |
|---|---|---|
| 🎖️ Raid Token | Boss Raid, อันดับ PvP (เพิ่มในตารางรางวัลซีซัน), World Boss | ใบกันแตก (🎖️ 6), วัตถุดิบขั้นสูง และไอเทมลับ (ภายหลัง) |
| 🎫 Boss Token (รายบอส) | ชนะบอสนั้น | แลกชิ้นเซ็ตของบอสนั้นที่ต้องการโดยตรง (ช่อง + เกรดที่เลือก) |

- **Raid Token เป็นคอลัมน์ในกระเป๋าเงิน** (`wallets.raid_token`) ผ่าน `WalletService.change` เดิม จึงมีบัญชีธุรกรรมและ row lock เหมือนเหรียญกับเพชร (roadmap กำหนดให้ตัดเงินใน transaction + lock ทุกสกุล)
- **Boss Token เป็นไอเทมใน `inventory_items`** (`boss_token:<bossId>`) เพราะเป็นของรายบอส เพิ่มคอลัมน์ต่อบอสไม่คุ้ม ตัดผ่าน `InventoryService.spend` ที่มีอยู่
- แลกชิ้นเซ็ต: ราคาตามเกรด (หายาก 20 · มหากาพย์ 50 · ตำนาน 120 Boss Token เริ่มต้น) ได้ชิ้นตรงกับที่เลือก
- **ชิ้นซ้ำ:** ถ้าสุ่มได้ชิ้นเดียวกับที่มีอยู่แล้ว (ช่อง + เกรดเดียวกัน) ได้ชิ้นตามปกติ ผู้เล่นแยกชิ้นส่วนเป็นหินได้เอง (ระบบแยกชิ้นส่วนมีแล้วจากเฟส 3) ไม่แยกอัตโนมัติ
- **ใบกันแตก:** ย้ายจากขายด้วย 💎 มาเป็น 🎖️ Raid Token (ตามที่เฟส 3 สัญญาไว้) เพชรเหลือใช้เติม stamina

### ข้อมูล (migration `1790800000000-add-raid`)

```
raid_progress  { user_id, boss_id, difficulty, clear_count, first_cleared_at }   unique (user_id, boss_id, difficulty)
```

## World Boss (5b)

### เอนจินต่อสู้แบบทีม (`team-battle.ts`)

`simulateBattle` เดิม **ไม่แตะ** (เพื่อรักษา replay) เพิ่มฟังก์ชันใหม่ `simulateTeamBattle(team: IFighter[], boss, seed, maxRounds)` ที่รองรับผู้ต่อสู้หลายคนฝั่งเดียว ใช้ซ้ำในเฟส 6–7 (Realtime PvP, Party Raid):
- ผลัดกันตามลำดับ SPD ทุกคนในทีมและบอสในรอบเดียวกัน บอสเลือกเป้าหมายสุ่มจากสมาชิกที่ยังรอด (เรียก RNG ลำดับคงที่)
- ใช้ตัวช่วยเอฟเฟกต์ชุดเซ็ตจาก 5a ชุดเดียวกัน (เอฟเฟกต์เป็นของ fighter แต่ละตัว)
- คืน event log (มี `actorIndex`) และ **ดาเมจรวมที่ทีมสร้างให้บอส** การตายของสมาชิกไม่จบการต่อสู้จนกว่าทีมจะตายหมดหรือครบรอบ
- ทดสอบ: ทีมตัวเดียวกับบอสธรรมดา ผลใกล้เคียง 1 ต่อ 1 (ไม่ต้องเหมือนบิต เพราะเป็นเอนจินใหม่), seed เดิมได้ผลเดิม

### กติกา

- **หนึ่งสัปดาห์หนึ่งตัว** (สัปดาห์ ISO ตามเวลาไทย) บอสมาจากตารางหมุนเวียน (`WORLD_BOSS_ROTATION` เป็นข้อมูล ตอนนี้มี ⚡ จักรกลพายุ ตัวเดียว หมุนซ้ำ) สร้างแถวของสัปดาห์ **ตอนมีคำขอแรกของสัปดาห์** (`INSERT ... ON CONFLICT DO NOTHING`) ไม่มี cron
- HP รวมคงที่ต่อบอส (เริ่มต้น 30,000) ทุกคนช่วยกันตี
- ตีได้ **วันละ 3 ครั้ง** แต่ละครั้งสู้สูงสุด 10 รอบ stamina −10 ดาเมจที่ทำได้ลด HP รวมทันที ตีหลัง HP หมดไม่ได้ (ทำจริงด้วยการล็อกแถวบอสระหว่างสู้ ดู "ผลที่ทำจริง (5b)")
- บันทึกดาเมจสะสมต่อคน (`world_boss_damage`) จัดอันดับตามดาเมจรวม
- **รางวัล (รับเอง ครั้งเดียวหลังสัปดาห์จบหรือบอสแตก):**
  - ทุกคนที่ตีอย่างน้อย 1 ครั้ง: 🪙 และ 🎖️ Raid Token ตามจำนวนครั้งที่ตี
  - ตามอันดับดาเมจ (อันดับ 1 / 2–3 / 4–10 / ที่เหลือ): เพิ่ม 🎖️ Raid Token, 🎫 Boss Token ของจักรกลพายุ และโอกาสได้ชิ้นชุดสายฟ้าเร็ว
  - **บอสแตกก่อนสัปดาห์จบ:** ทุกคนที่ร่วมได้โบนัสเพิ่ม และผู้ตีครั้งสุดท้าย (killing blow) ได้ชิ้นเซ็ตการันตี 1 ชิ้น
  - **บอสไม่แตก:** ยังได้รางวัลตามส่วนร่วมและอันดับ แต่ไม่มีโบนัสบอสแตก (ผู้เล่นน้อย ไม่ควรลงโทษทุกคน)
- รางวัลรับด้วย UPDATE แบบมีเงื่อนไข (`reward_claimed_at IS NULL`) ครั้งเดียว ส่งซ้อนได้รางวัลเดียว เหมือนรางวัลซีซัน PvP

### จุดเสี่ยงที่ต้องจัดการ

- **แถว HP เป็นจุดร้อน:** ทุกคนอัปเดตแถวเดียว ผู้เล่นหลักสิบคนไม่มีปัญหา (UPDATE สั้น ๆ) ถ้าเป็นหลักพันคนต้องแยกเป็นตัวนับย่อย บันทึกเป็นข้อจำกัดที่ยอมรับ
- ดาเมจรวมต้องอนุรักษ์ภายใต้การตีพร้อมกัน (ทดสอบกับ DB จริง: 20 request พร้อมกัน ผลรวม `damage` ในตารางต่อคน = HP ที่ลดลง)

## ผลที่ทำจริง (5a)

- **Golden test ของเอนจิน:** บันทึกผลของเอนจินเดิม 342 กรณี (ร่าง × สาย × seed, NPC, ด่านผจญภัย) ลง `battle-engine.golden.json` **ก่อนแก้เอนจิน** แล้วเพิ่มเอฟเฟกต์ ผลทุกกรณีตรงเดิมทุกบิต (`battle-engine.golden.spec.ts`) fighter ที่ไม่มี `effects` ไม่เรียก RNG เพิ่ม และ `toFighter` ไม่ใส่คีย์ `effects` เลยถ้าไม่มีเอฟเฟกต์ ข้อมูลที่เก็บไว้จึงหน้าตาเหมือนเดิม
- **เอฟเฟกต์ใน `simulateBattle`:** เผาไหม้ (ต่ออายุ ไม่ซ้อน ไม่สนเกราะและโล่ ดาเมจ 25% ของ ATK ผู้ใช้), โล่เริ่มต้น (ดูดก่อน HP), ฟื้นทุกเทิร์น (ไม่เกิน HP สูงสุด), โจมตีซ้ำ (หนึ่งครั้ง ไม่เป็นลูกโซ่ เป็นการโจมตีธรรมดา) event มีฟิลด์ใหม่ไม่บังคับ `kind` และ `absorbed` เฉพาะเมื่อเกี่ยวกับเอฟเฟกต์ หน้า replay แสดงข้อความให้
- **Raid ปิดตารางธาตุ (ต่างจากแผน):** ตอนจำลองพบว่าตารางธาตุทำให้ผลตายตัวตามคู่ธาตุ คือได้เปรียบชนะ 100% เสียเปรียบชนะ 0% ทุกระดับ ผู้เล่นแต่ละสายจึงได้ชุดเซ็ตแค่ 2 จาก 3 ชุดและไม่มีทางได้ชุดที่บอสธาตุข่มสายตัวเอง แก้ด้วยตัวเลือก `ignoreElements` (ค่าเริ่มต้นปิด จึงไม่กระทบ replay เก่า) เฉพาะการสู้บอส Raid ธาตุของบอสเหลือเป็นลายเรื่อง
- **สมดุลบอส** (สายทั้งสามเฉลี่ย ไม่ใช้ธาตุ): Normal ×1.125 ของค่าฐานร่างโต ≈ 72% (สายอ่อนสุด ≈ 52%) · Hard ×1.21 ของร่างสมบูรณ์ ≈ 50% · Nightmare ×1.26 ของร่างสูงสุด ≈ 31% ล็อกด้วย `raid-data.spec.ts` (ค่าเฉลี่ยใกล้เป้า และไม่มีสายไหนชนะต่ำกว่า 10%)
- **Raid Token:** คอลัมน์ `wallets.raid_token` (CHECK ≥ 0) ผ่าน `WalletService.change` เดิม ใบกันแตกขาย 🎖️ 6 แทน 💎 5 รางวัลซีซัน PvP เพิ่ม 🎖️ 20 / 12 / 6 / 2 ตามอันดับ
- **ชิ้นเซ็ต:** 16 แม่แบบ (4 เซ็ต × 4 ช่อง) ค่ารองตายตัวตามช่อง ค่าหลัก ×1.2 ของชิ้นธรรมดาเกรดเดียวกัน ตีบวกถึง +10 ทุกชิ้นของเซ็ต → โบนัสเปอร์เซ็นต์ ×1.5 เอฟเฟกต์ไม่เพิ่ม
- **กระเป๋าเต็ม:** ปฏิเสธก่อนสู้และไม่เสียโควตา เหมือนกันกับการแลก Boss Token (ไม่ตัด token ถ้าเต็ม)
- **ทดสอบกับ Postgres จริง** (`yarn test:integration`): โควตา 3 ครั้ง/วัน ยิงพร้อมกัน 8 request ผ่านพอดี 3 · ปลดล็อกตามร่างและระดับ · ชนะได้ Raid Token (x2 ครั้งแรก) + Boss Token + ชิ้นเซ็ตการันตี · แลกพร้อมกัน 3 request ผ่านพอดี 1 และแลกเกรดที่ยังไม่ปลดล็อกไม่ได้ · Raid Token ติดลบไม่ได้ · ชุด 4 ชิ้นแสดงเอฟเฟกต์ถูกต้อง
- **Integration spec เข้า repo แล้ว** (`monster-economy`, `equipment`, `pvp`, `raid` `.int-spec.ts`) มีตัวกันไม่ให้รันถ้า DB ไม่ใช่ local ที่ชื่อมี `test` หรือ `check` (`.env` ของโปรเจกต์อาจชี้ไป DB ที่ใช้ร่วมกัน)

## ผลที่ทำจริง (5b)

- **เอนจินทีม (`team-battle.ts`)** แยกสูตรโจมตีออกเป็น `rollHit` ใช้ร่วมกับเอนจิน 1 ต่อ 1 (golden test ผ่านเหมือนเดิม) ทีมกับบอสผลัดกันตาม SPD ทีมก่อนเมื่อเสมอ ไม่ใช้ RNG ตัดสินลำดับ บอสสุ่มเป้าจากสมาชิกที่ยังรอด เอฟเฟกต์ชุดเซ็ตทำงานเหมือน 1 ต่อ 1 ดาเมจเผาไหม้นับเป็นดาเมจที่ทำกับบอส event เป็นรูปแบบเดียวกับ 1 ต่อ 1 บวก `member` (สมาชิกที่ตีหรือถูกตี) หน้า replay เดิมจึงใช้ได้เลยเมื่อทีมมีคนเดียว
- **HP ที่บอสเข้าสู่การต่อสู้ = HP ที่เหลือของทั้งเซิร์ฟเวอร์** ดังนั้นการสู้ล้มบอสได้จริงและ `damageDealt` เท่ากับ HP ที่บอสเสียไปพอดี (ตัดที่ HP ที่เหลือ) ต่างจากแผนเดิมที่ใช้ `UPDATE ... GREATEST(...)` ตอนนี้ล็อกแถวบอส (`pessimistic_write`) ตลอดการจำลอง (สั้นมาก) ลำดับล็อกคงที่ (มอน แล้วบอส) ทุกคนล็อกเหมือนกันจึงไม่ deadlock
- **สัปดาห์:** ISO week ตามเวลาไทย (จันทร์ 00:00) แถวสัปดาห์สร้างโดยคำขอแรก (`INSERT ... ON CONFLICT DO NOTHING`) ทดสอบ 10 request พร้อมกันได้แถวเดียว ข้ามปี ISO ถูก (29 ธ.ค. 2025 = 2026-W01, 31 ธ.ค. 2026 = 2026-W53)
- **ความแรงบอส:** ×0.8 ของค่าฐานร่างสูงสุด HP 30,000 ดาเมจต่อการตี 1 ครั้งของมอนที่เลี้ยงดี (เฉลี่ย 3 สาย) ร่างโต ≈ 40 · ร่างสมบูรณ์ ≈ 170 · ร่างสูงสุด ≈ 450 ร่างสูงสุดตี 21 ครั้ง/สัปดาห์ได้ ≈ 9,500 จึงต้องร่างสูงสุดราว 3–4 คนถึงล้มบอสได้ภายในสัปดาห์ และไม่มีใครล้มได้ในวันเดียว (ล็อกด้วย `world-boss-data.spec.ts`) ผู้เล่นร่างโตมีส่วนร่วมน้อยมาก แต่ยังได้รางวัลเข้าร่วม
- **รางวัลสุ่มคงที่:** การสุ่มชิ้นเซ็ตตอนรับรางวัลใช้ seed จาก id ของบอสและผู้เล่น (`claimRolls`) ไม่ใช่นาฬิกา รับซ้ำหรือรับหลังเคลียร์กระเป๋าจึงได้ผลเดิม ไม่ใช้การ "ลองรับซ้ำ" เพื่อสุ่มใหม่ได้ กระเป๋าเต็มเมื่อมีชิ้นในรางวัลจะปฏิเสธก่อน ไม่เสียสิทธิ์รับ
- **ลำดับดาเมจเท่ากัน:** อันดับแบบ `RANK()` ผู้ที่ดาเมจเท่ากันได้อันดับเดียวกัน (รับรางวัลระดับเดียวกัน)
- **แลกชิ้นด้วย Boss Token ของบอสโลก** เพิ่มจากแผน: เฉพาะเกรดหายากและมหากาพย์ และต้องเคยรับรางวัลบอสนี้อย่างน้อยครั้งหนึ่ง (ไม่มีให้แลกตำนาน)
- **ตีบอสไม่นับ `wins`/`losses` ของมอน** เหมือน PvP และ Raid (`mode: 'world_boss'` ในบันทึกต่อสู้) ภารกิจ "ชนะการต่อสู้" นับเฉพาะครั้งที่ปลิดชีพบอส
- **ทดสอบกับ Postgres จริง** (`world-boss.int-spec.ts`): สร้างแถวสัปดาห์ครั้งเดียวเมื่อ 10 request พร้อมกัน · 6 คนตีพร้อมกัน ผลรวมดาเมจที่บันทึก = HP ที่ลดพอดี · โควตา 3 ครั้ง/วัน ยิงพร้อมกัน 8 request ผ่านพอดี 3 · ครั้งสุดท้ายตัดดาเมจที่ HP ที่เหลือ (40) บันทึกผู้ปลิดชีพ และปฏิเสธการตีต่อ · รับรางวัลพร้อมกัน 4 request จ่ายครั้งเดียว ได้ชิ้นการันตีเกรดมหากาพย์ · สัปดาห์ยังไม่จบรับไม่ได้ · อันดับเสมอได้อันดับเดียวกัน ไม่มี `user_id`/`username` ใน response · แลกพร้อมกัน 3 request ผ่านพอดี 1

## เพื่อนและเช่าตัว (5c)

### โปรไฟล์ผู้เล่น (ปรับปรุงจากเฟส 4)

- ตาราง `player_profiles { user_id unique, display_name, friend_code unique }` ย้าย `display_name` ออกจาก `pvp_defenses` มารวมที่เดียว (migration เติมจากข้อมูลเดิม) ทั้ง PvP, World Boss, เพื่อน ใช้ชื่อเดียวกัน
- **`friend_code`** สุ่ม 8 ตัวอักษร (ตัวอักษร/ตัวเลขที่ไม่สับสน) สร้างตอนแรกที่เปิดฟีเจอร์ เปลี่ยนไม่ได้ ผู้เล่นแจ้งรหัสให้เพื่อนเอง
- **PDPA:** เพิ่มเพื่อนด้วย friend code **เท่านั้น** ไม่มีการค้นหาด้วย username หรืออีเมล และไม่มี endpoint รายชื่อผู้ใช้ ทุก response แสดงเฉพาะ `display_name` + ข้อมูลเกม ไม่ส่ง `user_id` ของผู้อื่น (อ้างด้วย id ของความสัมพันธ์เพื่อน)

### เพื่อน

- ส่งคำขอด้วย friend code → อีกฝ่ายรับ/ปฏิเสธ ลบเพื่อนได้ทั้งสองฝ่าย
- ตาราง `friendships { user_low, user_high, requested_by, status, points, created_at }` เก็บคู่ **เรียงลำดับ id** (`user_low < user_high`) พร้อม unique index จึงส่งคำขอไขว้พร้อมกันไม่สร้างแถวซ้ำ (ถ้าอีกฝ่ายส่งมาแล้ว การส่งซ้ำ = รับคำขออัตโนมัติ)
- เพดานจำนวนเพื่อน (เริ่ม 30) และคำขอที่ค้างอยู่ (เริ่ม 20) กันสแปม
- **แต้มมิตรภาพ** (`points`) เพิ่มเมื่อมีปฏิสัมพันธ์ (ด้านล่าง) ใช้โชว์ และเป็นเงื่อนไขปลดล็อกในอนาคต (เฟสนี้ไม่แลกของ)

### เยี่ยมมอน และของขวัญ

- **เยี่ยม:** ดูมอนปัจจุบันของเพื่อน (ชื่อ ร่าง emoji ค่าพลังรวมอุปกรณ์ ระดับอายุ) อ่านอย่างเดียว กด "ทักทาย" ได้วันละครั้งต่อเพื่อน ได้แต้มมิตรภาพทั้งสองฝ่าย +1
- **ของขวัญ:** ส่ง **ไอเทมจากคลังของผู้ส่ง** (ของกิน/ใช้เท่านั้น) 1 ชิ้น ได้วันละ 3 ชิ้น เข้าคลังของผู้รับ **ไม่ส่งเหรียญหรือเพชร** (ผู้ส่งเสียของจริง จึงปั๊มเหรียญผ่านบัญชีรอง/เพื่อนกันเองไม่ได้ ตัดของด้วย `InventoryService.spend` ก่อนเพิ่มให้ผู้รับใน transaction เดียว) แต้มมิตรภาพ +2

### ตัวซัพพอร์ตและการเช่า

- **ตั้งตัวซัพพอร์ต** = snapshot มอนของตัวเอง (`support_units { user_id unique, fighter jsonb, display_name_at_set, set_at }`) เหมือนทีมป้องกัน PvP แต่แยกกัน (เก็บ `IFighter` ที่รวมอุปกรณ์และเอฟเฟกต์ stamina เต็ม) เปลี่ยนได้ทุก 30 นาที ต้องร่างโตขึ้นไป
- **เช่าได้:** ตัวซัพพอร์ตของ **เพื่อน** เท่านั้น (ไม่ใช่ทุกคน) ตีกับ World Boss ได้ **ตัวเช่า 1 ตัวต่อการตี** ตัวเช่า **ควบคุมโดยเอนจิน (AI)** เข้าร่วมในทีมของ `simulateTeamBattle` ตีบอสพร้อมผู้เช่า ไม่ได้ EXP/รางวัลใด ๆ (ดาเมจของตัวเช่า **ไม่นับ**เข้าอันดับของผู้เช่า แต่นับลด HP รวมของบอส)
- **ค่าเช่า:** ผู้เช่าจ่ายเหรียญให้เจ้าของ (เริ่มต้น 🪙 20 ต่อครั้ง ตัดจากผู้เช่าจริง) เจ้าของได้ 🪙 เท่านั้นบวก แต้มมิตรภาพ +3 มี **เพดานรายได้ต่อวันของเจ้าของ** (เริ่มต้น 🪙 200) เกินแล้วเช่าได้แต่เจ้าของไม่ได้เพิ่ม (ผู้เช่าไม่ต้องเสียเงินส่วนที่เกินเพดาน)
- เพราะผู้เช่าเสียเหรียญจริง และเช่าได้เฉพาะเพื่อน จึงไม่เปิดช่องปั๊มเหรียญจากอากาศ
- **ห้ามใช้ใน PvP:** เส้นทาง PvP ไม่รับ `supportId` และไม่มีตัวเช่าในเอนจิน 1 ต่อ 1 อยู่แล้ว (ทดสอบว่า `/pvp/battle` ปฏิเสธ body ที่มี `supportId`)
- ตัวเช่าใน Party Raid เฟส 7 ใช้ตัวซัพพอร์ตเดียวกัน

## ความเป็นส่วนตัว (PDPA) สรุป

- ทุกที่ที่ผู้เล่นเห็นผู้เล่นอื่น: เห็นเฉพาะ `display_name` (ที่ตั้งเอง) กับข้อมูลเกม
- เพิ่มเพื่อนด้วย friend code ที่เจ้าของแจกเอง ไม่ค้นหาจาก username/อีเมล
- ไม่มี response ไหนมี `user_id`/username/อีเมลของผู้อื่น ความสัมพันธ์อ้างด้วย id ของแถวความสัมพันธ์ (ผู้ใช้ต้องเป็นหนึ่งในสองฝั่งถึงเข้าถึงได้ ตรวจที่เซิร์ฟเวอร์ทุกครั้ง)
- ทดสอบ: สแกน JSON ผลลัพธ์ของทุก endpoint ใหม่ว่าไม่มี `user_id`/`username` ของผู้อื่น (ทำแล้วในเฟส 4 ทำซ้ำ)

## ทดสอบ

- **เอนจิน:** golden replay ของเอนจินเดิม (บิตต่อบิต) · เอฟเฟกต์แต่ละชนิด (เผาไหม้ ต่ออายุไม่ซ้อน, โล่ดูดก่อน HP, ฟื้นไม่เกิน HP สูงสุด, โจมตีซ้ำไม่เป็นลูกโซ่) · เอนจินทีม (ทีมเดียว ≈ 1 ต่อ 1, seed เดิมผลเดิม, บอสเลือกเป้าเฉพาะผู้รอด)
- **ชุดเซ็ต:** `calcSetBonuses` 2/4 ชิ้นและผสม 2+2 (มี spec แล้ว ขยายเรื่องเอฟเฟกต์และ ×1.5 ที่ +10) · ชิ้นเซ็ตมีค่ารองตายตัว
- **สมดุล:** บอส Raid แต่ละระดับ: มอนที่เลี้ยงดีของร่างที่กำหนดชนะราว 70% / 50% / 30% (Normal / Hard / Nightmare) โดยไม่มีชุดเซ็ต และชนะง่ายขึ้นพอประมาณเมื่อใส่เซ็ตครบ · World Boss: ดาเมจรวมของผู้เล่นปกติต่อวันไม่ทำให้บอสแตกใน 1 วัน แต่แตกได้ภายในสัปดาห์เมื่อผู้เล่นเข้าร่วมพอ (ตัวเลข HP คำนวณจากดาเมจต่อครั้งที่จำลอง)
- **DB จริง (ต้องมี Postgres):** โควตา Raid วันละ 3 ครั้ง ยิงพร้อมกัน 8 request ผ่านพอดี 3 · กระเป๋าเต็มแล้วปฏิเสธก่อนสู้และไม่ตัดโควตา · แลก Boss Token พร้อมกันไม่ติดลบ · World Boss 20 request พร้อมกัน ผลรวมดาเมจตรงกับ HP ที่ลด · ตีหลัง HP หมดถูกปฏิเสธ · รับรางวัลสัปดาห์พร้อมกันได้ครั้งเดียว · คำขอเพื่อนไขว้พร้อมกันได้แถวเดียว · ส่งของขวัญพร้อมกันตัดของไม่ติดลบ · เพดานรายได้ค่าเช่า · ไม่มีตัวเช่าใน PvP
- ย้ายสคริปต์ทดสอบ DB ของเฟส 2–4 เข้า repo เป็น integration spec **ก่อนเริ่ม 5a** ✅ ทำแล้ว (ทุกเฟสจากนี้เพิ่ม spec ในนั้น)

## ผลที่ทำจริง (5c)

- **โปรไฟล์กลาง (`player_profiles`):** ชื่อสนามย้ายจาก `pvp_defenses` มาที่นี่ (migration เติมชื่อเดิมให้และลบคอลัมน์เดิม; `down()` ใส่กลับ ทดสอบ down/up จริงใน transaction) PvP (รายชื่อคู่ต่อสู้, ประวัติ, อันดับ) และอันดับบอสโลกอ่านชื่อจากโปรไฟล์ `POST /pvp/defense` ที่ส่ง `displayName` มายังใช้ได้ เปลี่ยนชื่อในโปรไฟล์ให้ ผู้เล่นที่ไม่มีโปรไฟล์ใช้ชื่อเริ่มต้น `ผู้ฝึก#xxxx` (hash ของ id) ไม่ใช่ username
- **เพื่อน:** ขอด้วยรหัสเพื่อนเท่านั้น (8 ตัวอักษร ไม่มี 0/O/1/I/L; ไม่มี endpoint ค้นหาผู้ใช้) แถวเดียวต่อคู่ เรียง id (`CHECK user_low < user_high`) ถ้าสองคนขอกันพร้อมกันได้แถวเดียวและเป็นเพื่อนกัน เพดานเพื่อน 30 (นับคำขอที่ส่งแล้วรอ) และคำขอค้างต่อคน 20 ทักทายวันละ 1 ครั้งต่อเพื่อน ล็อกแถวเพื่อนกันส่งซ้อน ส่งของขวัญเป็นไอเทม **ของกินและใช้จากร้านค้า** (ไอเทมที่ใช้กับมอน) จากคลังผู้ส่ง วันละ 3 ชิ้น (ล็อกด้วย advisory lock ต่อผู้ส่ง เพราะเพดานนับรวมทุกเพื่อน)
- **ตัวซัพพอร์ต** แยกจากทีมป้องกัน PvP (ตาราง `support_units`) เปลี่ยนได้ทุก 30 นาที ร่างโตขึ้นไป
- **เช่าตัวใน World Boss:** ตรวจว่าเป็นเพื่อนที่ตอบรับแล้ว ตอบข้อความเดียวกัน (`Support unit is not available`) สำหรับไม่ใช่เพื่อน/ตัวเอง/ไม่มีตัวนั้น เพื่อไม่ให้เดา id ได้ ค่าเช่า 🪙 20 ผู้เช่าจ่ายเท่าที่เจ้าของยังรับได้ภายใต้เพดาน 200/วัน (เกินเพดานเช่าฟรี) **ล็อกกระเป๋าเงินสองฝั่งเรียงตาม id ก่อน** (`WalletService.lockWallets`) เช่าไขว้กันพร้อมกันจึงไม่ deadlock (ทดสอบ) ลำดับล็อกทั้งหมด: มอนผู้เช่า → แถวบอส → กระเป๋าเงิน (เรียง id) → แถวเพื่อน
- **ดาเมจรายสมาชิก:** เอนจินทีมคืน `damageByMember` (ตัดที่ HP ที่เหลือจริง เผาไหม้นับให้ผู้จุด) ดาเมจของผู้เช่านับอันดับ ดาเมจของตัวเช่าลด HP บอสและบันทึกใน `rentals.ally_damage` ค่าคงที่ที่ทดสอบ: HP ที่บอสเสีย = ผลรวมดาเมจรายผู้เล่น + ผลรวม `ally_damage` ผู้ที่ตีครั้งสุดท้ายได้เครดิตปลิดชีพเป็นผู้เช่า (คนที่กดตี) แม้ตัวเช่าเป็นคนลงดาบสุดท้าย
- **ห้ามใช้ตัวเช่าใน PvP โดยโครงสร้าง:** เส้นทาง PvP ไม่มีพารามิเตอร์ตัวเช่าและเอนจินเป็น 1 ต่อ 1 (unit test: ส่ง `supportId` เข้า `/pvp/battle` ก็ถูกละเลย `battle()` รับแค่ 2 อาร์กิวเมนต์) แอปไม่ได้เปิด `whitelist` ใน ValidationPipe จึงไม่ปฏิเสธ field แปลกปลอม แต่ไม่มีผล
- **Frontend:** แท็บ **เพื่อน** (โปรไฟล์และรหัส, เพิ่มเพื่อน, คำขอเข้า/ออก, รายชื่อ, เยี่ยม/ทักทาย/ของขวัญ/ลบ, ตัวซัพพอร์ต) หน้าบอสโลกมีตัวเลือกเช่าตัวและสรุปผลมีดาเมจและค่าเช่าของตัวเช่า replay รู้จักสมาชิกทีม (ชื่อตัวเช่า แถบ HP ของผู้เล่นไม่ปนกับตัวเช่า) หัวข้อในคู่มือ
- **ทดสอบกับ Postgres จริง** (`social.int-spec.ts` 15 tests): โปรไฟล์ได้รหัสเดียวเมื่อสร้างพร้อมกัน 8 request · ขอไขว้พร้อมกันได้แถวเดียว · คำขอค้างเกิน 20 ถูกปฏิเสธ · ทักทายพร้อมกัน 4 request ผ่านพอดี 1 · ส่งของขวัญพร้อมกัน 5 request ผ่านพอดี 3 และของย้ายไปผู้รับถูกต้อง · **ไม่มี `user_id`/`username` ของผู้อื่นใน response ของรายชื่อเพื่อน เยี่ยม และรายการให้เช่า** · เช่าแล้วผู้เช่าจ่ายเจ้าของ · เพดานรายได้ (190 → จ่าย 10 → ฟรี) · ผู้เช่าที่เงินไม่พอถูกปฏิเสธโดยไม่เสีย stamina และโควตา · เช่าไขว้พร้อมกันไม่ deadlock · migration ย้ายชื่อเดิมและสร้างรหัสที่ถูกต้อง
- **ความไม่นิ่งของ test ที่เจอ:** รันรอบแรกหลังเพิ่ม spec มี test ล้มหนึ่งตัวแล้วผ่านติดกัน 13 รอบ เวลาตรงกับเที่ยงคืนเวลาไทยวันที่ 1 พ.ย. (รอยต่อเดือนของซีซัน PvP) สาเหตุที่น่าจะเป็นที่สุดคือ spec ของ PvP/บอสโลกคำนวณ `season`/`week` ครั้งเดียวตอนเริ่ม จึงแก้ให้คำนวณตอนใช้ และให้ test ตีบวกแตกมีเหรียญ/หินพอไม่หมดก่อนแตก ยืนยันไม่ได้ว่าตัวที่ล้มคือตัวไหน
